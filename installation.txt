====================================================================
تشغيل P-Sale Ultra Cloud في الخلفية عبر PM2 — دليل التثبيت الكامل
====================================================================
الهدف: تشغيل السيرفر (Backend) والعميل (Frontend) في الخلفية بشكل
دائم، مخفيين عن الموظفين (لا نافذة ولا أيقونة)، مع:
- إعادة تشغيل تلقائية عند أي خطأ (auto-restart)
- تشغيل تلقائي عند إقلاع الجهاز وتسجيل الدخول
- إدارة سهلة بالإيقاف وإعادة التشغيل عبر أوامر واحدة

--------------------------------------------------------------------
0) المتطلبات المسبقة (تحقق قبل البدء)
--------------------------------------------------------------------
- Node.js مثبت:            node --version        (يُفضل v20+)
- npm مثبت:                npm --version
- MySQL/MariaDB شغال       (السيرفر يتصل عبر server/.env)
- ملف server/.env موجود وصحيح (المنفذ 3005)
- المشروع في:              C:\Users\Weeshi\p-sale-ultra-cloud

--------------------------------------------------------------------
1) تثبيت PM2 (مرة واحدة فقط)
--------------------------------------------------------------------
افتح PowerShell ونفّذ:

    npm install -g pm2

تحقق من التثبيت:

    pm2 --version          (يجب أن يطبع رقم الإصدار مثل 7.0.3)

ملاحظة: أول تشغيل لأي أمر pm2 ينشئ "daemon" في الخلفية تلقائياً
ولن يظهر أي شيء في الشاشة — هذا طبيعي ومطلوب.

--------------------------------------------------------------------
2) تشغيل السيرفر والعميل في الخلفية (الطريقة الموصى بها)
--------------------------------------------------------------------
في المشروع أنشأنا ملف إدارة موحداً اسمه:

    ecosystem.config.cjs

يحتوي تعريفاً جاهزاً لعمليتين:
    - psale-server : يشغّل tsx watch src/app.ts  (السيرفر على 3005)
    - psale-client : يشغّل vite dev server        (العميل على 5175)

لبدء العمليتين معاً (من جذر المشروع):

    cd C:\Users\Weeshi\p-sale-ultra-cloud
    pm2 start ecosystem.config.cjs

النتيجة المتوقعة: جدول فيه صفان باسم psale-server و psale-client
بحالة online.

تحذير مهم (Windows):
لا تستخدم الأمر  pm2 start npm --name ... -- run dev
لأنه لا يعمل على Windows (يسبب خطأ "Script not found" وسجل
أخطاء مليئاً بـ NPM.CMD SyntaxError). استخدم ecosystem.config.cjs
دائماً.

--------------------------------------------------------------------
3) التحقق من أن كل شيء يعمل
--------------------------------------------------------------------
عرض حالة العمليتين:

    pm2 list

يجب أن يكون كلاهما online و ↺ يساوي 0 (لا إعادة تشغيل).

اختبار السيرفر (يجب أن يعيد {"status":"ok","db":"connected",...}):

    Invoke-WebRequest http://localhost:3005/api/health

اختبار العميل (يجب أن يعيد HTTP 200):

    Invoke-WebRequest http://localhost:5175

افتح المتصفح:  http://localhost:5175   ← سجّل الدخول وجرّب.

--------------------------------------------------------------------
4) التشغيل التلقائي مع إقلاع الجهاز (Windows)
--------------------------------------------------------------------
PM2 نفسه لا يدعم "pm2 startup" على Windows. الحل الصحيح:

أ) تثبيت أداة التشغيل التلقائي (مرة واحدة):

    npm install -g pm2-windows-startup

ب) تسجيلها:

    pm2-startup install

    (النتيجة المتوقعة: "Successfully added PM2 startup registry entry.")

ج) حفظ قائمة العمليات الحالية:

    pm2 save

    (النتيجة المتوقعة: "Successfully saved in ...\dump.pm2")

الآن عند إعادة تشغيل الجهاز وتسجيل الدخول، يبدأ PM2 تلقائياً
ويعيد تشغيل psale-server و psale-client تلقائياً.
(ملاحظة: التسجيل يتم على مستوى المستخدم HKCU\...\Run — يتطلب
تسجيل دخول المستخدم نفسه Weeshi.)

للإلغاء لاحقاً:

    pm2-startup uninstall

--------------------------------------------------------------------
5) أوامر الإدارة اليومية
--------------------------------------------------------------------
عرض الحالة:
    pm2 list

عرض السجلات (مباشرة):
    pm2 logs
    pm2 logs psale-server
    pm2 logs psale-client

إعادة تشغيل:
    pm2 restart psale-server
    pm2 restart psale-client
    pm2 restart all            (الكل)

إيقاف (بدون حذف من القائمة):
    pm2 stop psale-server
    pm2 stop all

حذف نهائي من القائمة:
    pm2 delete psale-server
    pm2 delete all

مراقبة CPU/RAM:
    pm2 monit                  (اضغط q للخروج)

تحديث قائمة التمهيد بعد تغيير العمليات:
    pm2 save

تفريغ سجلات الأخطاء القديمة:
    pm2 flush

--------------------------------------------------------------------
6) استكشاف الأخطاء
--------------------------------------------------------------------
- الحالة "errored" في pm2 list:
      pm2 logs psale-server     ← اقرأ آخر خطأ
      pm2 restart psale-server

- سجل الأخطاء يعرض NPM.CMD SyntaxError:
      هذا من محاولة قديمة بأمر npm الخاطئ. افرغه:
      pm2 flush
      (لا يؤثر على الخدمة إذا كانت الحالة online و ↺ = 0)

- المنفذ 3005 أو 5175 مشغول:
      netstat -ano | findstr 3005
      أوقف العملية الممسكة للمنفذ ثم:  pm2 restart all

- العميل يعمل لكن /api لا يستجيب:
      تأكد أن psale-server online
      وافحص سجلاته: pm2 logs psale-server

--------------------------------------------------------------------
7) ملاحظات تشغيلية مهمة
--------------------------------------------------------------------
- الحالة الحالية هي نسخة التطوير (tsx watch + Vite dev) وهي
  مناسبة للاستخدام المستمر على جهاز واحد.

- tsx watch يعيد تشغيل السيرفر عند أي تغيير في ملفات server/src.
  لا تعدّل الكود أثناء ساعات العمل حتى لا ينقطع الخدمة فجأة.

- لقراءة سجلات الأخطاء المتراكمة في ملفات PM2:
      C:\Users\Weeshi\.pm2\logs\psale-server-error.log
      C:\Users\Weeshi\.pm2\logs\psale-client-error.log

- لا تمسح بيانات الموقع (Site Data) من المتصفح بعد هذا الإعداد،
  لأن بيانات الأوفلاين (IndexedDB) مخزنة في المتصفح نفسه.

- ابقِ مهمة النسخ الاحتياطي اليومية شغالة:
  "PSaleUltraDailyBackup" في Windows Task Scheduler (يومياً 02:00).

- النسخة الإنتاجية النهائية (أسرع/أثبت) لاحقاً: استخدم build
  بدلاً من dev مع reverse-proxy (nginx/Caddy) — خارج هذا الدليل.
